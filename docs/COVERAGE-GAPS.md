# 会漏掉哪些渗透测试？（覆盖模型的遗漏面清单）

> 问题：dsh-voredteam 这种"资产清单 × 浅测/深测状态 + 阶段门"的作业模式，会不会系统性漏掉某些渗透测试？
> 结论：**会**。而且漏的方式不是"某个插件没写"，是**账本看得见的东西太少**：
> 阶段门只证明"每个资产都有状态"，不证明"每个资产被哪些测试类别打过"。
> 本文件把漏面逐条列清（含代码位置与复现命令），并给出修法与代价。
>
> 完成的部分见 §5（误拦/漏放两类门禁缺陷 + na 不可漂白），**本轮（六阶段重构）已落地的部分见 §6**；
> 仍待做的只剩 S5（来源类别 7 类）与 S7（多环境/vhost 合并）。
>
> **现状更新**：作业法收敛为**六阶段** —— **P1 起点 / P2 信息收集（逐资产信息全采）/ P3 浅层（核实信息收集 + 浅层测试）/ P4 中间层（核实浅层 + OWASP Top 10）/ P5 深层（读全量 + 核验中间层 + 漏洞验证）/ P6 成果**，
> 判据从"一个 `s2/s3` 布尔位"升级为 **`asset_checks` 六张矩阵**（info / verifyInfo / shallow / verifyShallow / owasp / deep）。见 `docs/ARCHITECTURE.md` §二之二。

---

## 一、结构性遗漏（账本维度，最主要的一类）

| # | 漏面 | 机制（代码位置） | 具体会漏掉什么 |
|---|---|---|---|
| S1 | **深测只有一个布尔位** | `assets.s3` 是单字段；`coverage()` 只判 `s3 ∈ {done,na}`（`store.js`）。SKILL 里的深测清单是**建议文本**，没有任何机器位置记录"这条资产跑过哪些类别" | 同一接口上除首个想到的漏洞族之外的**全部**：测了 IDOR 就算覆盖，SQLi / SSRF / 参数污染 / 越权写 / 竞态 / 上传绕过全都没有痕迹。这是最大的一条 |
| S2 | **na 曾是漂白通道**（已修） | `updateAsset` 原先不校验理由，`notes` 可选；门禁只认 `∈{done,na}` | 把难的面标 `na` 即可 100% 出关。**已修**：无理由/理由过短一律拒绝 + 覆盖率单列 `naShallow/naDeep/naNoReason` 与"真测过"百分比 |
| S3 | **priority 自报，`<3` 合法免除深测** | `DEFAULT_DEEP_MIN_PRIORITY = 3`；`priority` 由登记方写入，无人复核（`store.js`） | 登记时给 1~2 分就等于合法跳过深测，账本上不留缺口。没有"优先级凭什么这么给"的复核点 |
| S4 | **没有"未测面"这个一等对象** | 黑板只有 facts / intents / hints / dead；`dead` 只记"试过但没成" | **"从没想到要测"的面在账本里不产生任何痕迹**，报告无法声明未覆盖面，客户据此无法判断残余风险（P4 出关只查 s2/s3 缺口） |
| S5 | **来源类别只有 7 类** | `SOURCE_CLASSES = [domain subdomain ip port url endpoint js]`，`sourcesMissing` 只比这 7 类 | 云 / 凭据 / 仓库 / 客户端 / 证书透明度 / DNS 历史 / 接口文档 / 邮件与网络边界**永远不算来源缺口**，P1 可以在完全没碰它们的情况下出关 |
| S6 | **凭据/角色维度缺失** | `cred` 只是 `kind` 之一，没有角色/权限级别字段 | 越权（价值最高的漏洞族）需要 ≥2 个不同权限账号；客户没给账号时"三态对照"做不了，可账本照样显示 `s3=done`。缺前置条件这件事没有登记处 |
| S7 | **唯一键合并环境与虚拟主机** | `assets` 唯一索引 `(project_id, kind, value)` | 同一 IP 上的多个 vhost（Host 头维度）、staging 与 prod 同域名的场景被并成一行 → 少测一整个环境/站点（而 staging 往往防护更弱、数据更真） |
| S8 | **复核只复核结论，不复核覆盖** | `reviewer` 卡片职责是"对一条结论确认/挑战" | 没有任何角色挑战"该测而没测的面"；账本是自证的 |

**一句话**：现在的账本回答"这条资产测完没有"，回答不了"这条资产被哪些手段打过"和"哪些面根本没进清单"。

## 二、无人负责的横向面（12 张角色卡里没有"我来测"的条目）

| 面 | 现状 | 影响 |
|---|---|---|
| HTTP 请求走私 / 缓存投毒 / 缓存欺骗 / Host 头注入 | `api-security` 覆盖 GraphQL/gRPC/WS；`web-injection` 覆盖注入族，都没点这两类 | 网关/反代架构下常见的高危面被整片漏掉 |
| CORS 误配的**利用** | `recon` 只把它记成线索（"CORS 允许来源"），无人负责验证可利用性 | 线索停在清单里，不进深测 |
| 子域接管的**利用** | 同上：`recon` 记 CNAME 指向 CDN/云存储为"接管线索" | 只登记不验证 |
| Web 加固项（CSP / 点击劫持 / HSTS / Cookie 属性 / 安全头） | 无 | 合规类交付物缺项，客户安全基线无法评估 |
| 前端第三方依赖 / SDK 版本的供应链 CVE | `component-cve` 偏服务端指纹；`js-reverse` 只提取接口与密钥 | 前端依赖漏洞（jQuery/旧版 SDK）无人测 |

## 三、门禁与"能不能测"的冲突（**实测过的事实**）

### 3.1 误拦：合法测试被挡在门外（已修）

爆破规则原本是 `/\b(?:--password-file|--passwords|-P)\s*[^\s|;&]+/i` —— `/i` 让它连**工具名里的 `-p`** 都命中：

```
bloodhound-python …        → 匹配 "-python"
impacket-psexec …          → 匹配 "-psexec"
impacket-… -no-pass        → 匹配 "-pass"
```

后果不是"更安全"，而是内网凭据复用 / AD 枚举 / 无密码登录验证这些**合法**动作全被拦。
量化（`tests/_skill-guard-scan.mjs`，对 720 份内置技能、83670 行围栏命令跑 `scanCommand`）：

| | 判定会被拦 | 其中"禁止爆破" |
|---|---|---|
| 修复前 | **960 行** | 835 行（绝大多数是上述误报） |
| 修复后 | **217 行** | 87 行（真阳性：hydra / netexec / `-P 字典` 等） |

修法：工具名必须在**命令词位置**（`^`/`;`/`|`/`&`/空白之后）才算命中；去掉裸 `-P` 规则（hydra/medusa/ncrack/wpscan 都已被工具名规则覆盖）；补 `nxc`（netexec 的新名字，原先是个绕过口子）。

### 3.2 漏放：速率纪律形同虚设（已修）

```
修复前： nmap -p- -T4            → 放行（-T4 被当成"有速率控制"，它只是时序模板）
        nmap -p- --min-rate 5000 → 放行（--min-rate 是速率**下限**，越扫越快）
        nmap -p- --max-rate 20000→ 放行（--max-rate 没有上限夹紧）
修复后： 三者全部拦截；上限 = defaultRps × 60，夹紧 100..1000；`--top-ports 100` 放行
```

### 3.3 内置技能与本项目门禁冲突（已写进技能纪律）

`vendor/skills/` 里 1000+ 份外部技能给的是**通用写法**，其中 217 行命令会被本项目门禁拦（例：`nmap -sS -p- --min-rate 1000 -T4`、无 `-rate` 的 `ffuf`/`nuclei`/`gobuster`、`hydra`、`netexec` 喷洒）。
这不是缺陷（门禁更严是设计目标），但**必须在纪律里写明**：读它们是取思路与 payload，落到命令要改成本项目的限速写法；被拦按拒绝文案改写，不要绕。已写入 `skills/vore-rate-discipline/SKILL.md`。

## 六、六阶段重构：把「测得够不够深」变成数据（本轮）

作业法从五阶段再进一步收敛为**六阶段**，核心变化是：**信息收集独立成阶段，且每一层先核实上一层的产出，再做本层的工作**。

```
P1 起点 → P2 信息收集 → P3 浅层（核实信息收集 + 浅层测试） → P4 中间层（核实浅层 + OWASP Top 10） → P5 深层（读全量 + 核验中间层 + 漏洞验证） → P6 成果
```

| 原来会漏的 | 现在的机器判据 |
|---|---|
| 深测只有一个布尔位（S1） | `asset_checks` **六张矩阵**：`info`（信息收集 12 项 + 按 kind 追加）/`verifyInfo`（浅层核实信息收集）/`shallow`（浅层测试 8 项）/`verifyShallow`（中间层核实浅层）/`owasp`（A01–A10）/`deep`（8 类漏洞）；出关逐项判，缺口按 `asset:key` 列出 |
| "采到的信息是不是真的"没人管 | **`verifyInfo`**：逐项判 `ok`/`wrong`/`unknown`；`wrong`（例：版本只来自响应头）必须在下一步被独立复算（`reviewed`）才放行 |
| 浅层"只跑一遍指纹就算过" | **P2 信息收集**独立成阶段（12 项 BASE 逐项要结论与证据）；**P3 浅层测试**另有 8 项：`fp` 指纹行为验证 / `pathTruth` 路径真值 / `params` 参数面 / `authEdge` 鉴权边界 / `errLeak` 错误泄露 / `expose` 暴露面 / `lowFuzz` 低频模糊 / `compHint` 组件线索 |
| 上一层的结论不复算就沿用 | **`verifyShallow`**（中间层核实浅层：结论有没有证据、有没有漏）+ 中间层的 OWASP 结论必须在深层 `reviewed` 才算数 |
| `na` 可漂白（S2） | `na`/`wrong`/`unknown` 一律要理由（太短也拒）；`hit` 必须给证据 |
| `priority` 自报免除后半程（S3） | `priority ≤ 2` 登记时必须给理由，且**后四张矩阵按 priority ≥ 3 收敛** —— 降级是"写了理由的可审计动作"，不是悄悄免测 |
| 没有"未测面"这个概念（S4） | `untested` 表 + `bb_untested_add`（必须写 why）+ P6 出关要求 `declareUntested` |
| 越权类缺"需要 ≥2 角色"的前置（S6） | 未测面账本承载"缺凭据/缺授权做不了" → 变成显式交付项，而不是静默跳过 |
| 复核只复核结论、不强制（S8） | `bb_fact_review`（confirm/challenge + 独立证据）；P6 出关要求**每条漏洞事实都有复核记录** |
| 回灌只靠人自觉回头 | 新增资产 → 六张矩阵缺口同时重现 → 阶段**自动退回 P1 起点**并置 `reflow_pending`（连「连续一轮 0 新增」的饱和判定一起作废）→ 必须再收一轮确认；`phase_note` / `reflow_source` 记明来源 |

**六阶段的出关条件**：
P1 饱和 → P2 `info` 全项 → P3 `verifyInfo` 全项 + `shallow` 8 项 → P4 `verifyShallow` 全项 + `owasp` A01–A10 → P5 `deep` 8 类 + `wrong` 已复算 + 中间层结论已核验 → P6 未测面声明 + 漏洞事实复核。

断言：`tests/smoke.mjs` **46 项**（含"P3 出关要同时核实采集与浅层测试""wrong 必须复算才放行""OWASP 结论必须被深层核验""回灌把阶段退回 P1 起点且必须再收一轮才解封""低优先级必须给理由""旧五阶段命名与 stage 的一次性升级"）；
`tests/load.mjs` 22 项；面板侧断言在 `plugins/vore-console/tests/`（八泳道 + 六矩阵）。

**回灌语义（最严口径）**：新增资产（JS 逆向 / 目录探测 / 配置文件 / 证书）→ 阶段**退回 P1 起点**：饱和判定作废（`reflow_pending=1`）→ 必须先再收一轮确认「连续 0 新增」→ 再给这批新资产走 P2→P5 六张矩阵。

**未做（仍然待补）**：§4 的 3（`SOURCE_CLASSES` 只有 7 类）与 5（`assets` 缺 `env`/`vhost` 维度）。
