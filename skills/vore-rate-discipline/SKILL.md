# 速率与门禁细则（vore-rate-discipline）

> dsh-voredteam **只有一条门禁**。其余门禁（阶段门、覆盖矩阵、强制流程）已全部移除——严谨性由事实纪律与独立复核保证。
> 但这一条是**确定性拦截**：`vore-guard` 会在命令执行前拦下违规命令。**被拦时不要换写法绕过**，改走下面的合规路径。

## 一、三条禁止/约束

### 1. 禁止 DDoS（洪水 / 压测 / 连接耗尽）
被拦的特征：`hping3 --flood`、`wrk`、`vegeta`、`siege`、`jmeter`、`ab -n 大数`、`slowloris`/`slowhttptest`/`t50`、`nmap --script dos|broadcast`、`xargs -P ≥10` 并发压请求、`while true; do curl`、`seq N | xargs -P`。

**合规替代**：单点最小验证——1~3 个请求确认现象；需要覆盖度时按清单**串行**请求，间隔 ≥0.5s。
> 竞态类问题也用"限速内并发"验证（同一时刻 ≤3 个请求，跑 2~3 轮），禁止压测式放大。

### 2. 禁止爆破（在线字典 / 凭据填充）
被拦的特征：`hydra`/`medusa`/`ncrack`/`patator`/`crowbar`、`kerbrute`、`netexec`/`crackmapexec`/`nxc` 喷洒、`nmap --script *-brute`、`wpscan --passwords`、`--password-file`/`--passwords <字典>`、脚本里 `for x in $(cat pass*)`。
**不拦**（这些是合法的凭据复用/枚举，别自己吓自己）：`impacket-*`（含 `-hashes`/`-no-pass`/`-k`）、`bloodhound-python`、`smbclient -U user%pass`、`curl -u user:pass`、`sqlmap`、`hashcat`/`john`、`ssh -i key`。工具名必须出现在**命令词位置**才算命中，URL/路径里的同名子串不算。

**合规替代**：
1. 用**已知/泄露/默认凭据**做单次登录验证（≤3 次尝试），命中即停；
2. 换面找凭据：JS 硬编码、配置文件泄露、`.git`/备份文件、接口越权读他人配置；
3. **离线**哈希破解（`hashcat`/`john`）不受限——它在本地跑，不打目标；
4. 弱口令验证例外：写清理由 + 极小字典（≤20 条）+ 严格限速（≤0.5 req/s）+ 命中即停，并在事实里登记"用了哪 20 条"。

### 3. 模糊测试必须智能化低频
被拦的特征（缺显式限速参数，或超阈值）：

| 工具 | 必须带 | 上限 |
|---|---|---|
| `ffuf` | `-rate N`（或 `-p` 延迟） | ≤50（建议 `-rate 20`） |
| `feroxbuster` | `--rate-limit N` | ≤50 |
| `dirsearch` | `-t N` + `--delay` | ≤10（建议 `-t 5 --delay=0.2`） |
| `gobuster` | `-t N` + `--delay` | ≤10 |
| `wfuzz` | `-t N` + `-s` | ≤10 |
| `nuclei` | `-rl N -c M` | ≤50（建议 `-rl 20 -c 5`） |
| `arjun` | `-t N` | ≤10 |
| `nmap` 全端口/大范围（`-p-`、`-p 1-65535`、跨度 ≥2000 的 `-p a-b`、`--top-ports ≥1000`） | **必须** `--max-rate N` | ≤300（上限 = defaultRps × 60，夹紧 100..1000） |
| `nmap` 小范围（`-p 80,443`、`--top-ports 100`、`-T2 --max-rate 50`） | 不需要额外参数 | 放行 |

`nmap` 三个坑：**`-T2/-T3/-T4` 不算速率控制**（只是时序模板，不限制每秒包数）；**`--min-rate` 是速率下限**，会被拦；`--max-rate` 超过上限会被拦。

## 二、样本策略（"智能化"的具体含义）

1. **先小样本**：字典类任务先跑 ≤50 条（挑最有代表性的：常见路径/参数名/已见过命名风格），确认**命中特征**（404/200/长度差异/时间差）。
2. **判据先行**：放大之前先写清"什么算命中"（状态码 + 响应长度区间 + 关键词），否则放大只是制造噪声。
3. **去重**：同一 URL+参数只测一次；已有事实里出现过的目标不要重跑（先 `bb_graph`）。
4. **命中即停**：一旦确认，停止该字典的其余请求，转人工/精确验证。
5. **WAF/生产目标降到 ≤1 req/s**，并优先只读、单点、样例化验证。
6. **记录请求量**：在事实里写清"发了多少请求、速率多少"——这是合规证据，也是事后复盘的依据。

## 三、被拦之后怎么办

`vore-guard` 的拒绝文案自带降级路径，标准动作：

1. **读拒绝原因**（它会写进 `<workspace>/vore-guard-log.md` 并直接回给你）；
2. **按它给的合规写法改写命令**（补限速参数 / 降线程数 / 换单点验证）；
3. 若认为该动作**确实必要且合规**（例如用户的授权明确要求某类验证），走 `ask_user` 呈报理由，等用户批准后再执行，并在事实里登记批准来源；
4. **绝不做的事**：换等价工具绕过、把 `-P 50` 拆成 50 次单发、用 `curl` 手写循环替代 `wrk`——这些同样违规。

> **内置第三方技能里的命令要按本项目门禁改写**：`vendor/skills/` 里那 1000+ 份外部技能（Claude-Red / reverse-skill / Anthropic 等）给的是**通用写法**，其中约 200 行命令会被本项目门禁拦（实测：`nmap -sS -p- --min-rate 1000 -T4`、无 `-rate` 的 `ffuf`/`nuclei`/`gobuster`、`hydra`、`netexec` 喷洒等）。读它们是为了**思路与 payload**，落到命令时必须补/改成本项目的限速参数；被拦是预期行为，按拒绝文案改写，不要绕。
